# Power Automate インポート パッケージの作成

## 基本方針

- **要件と環境の値は推測しない。** 依頼の解釈が複数に分かれ、結果のフローが変わる場合や、リスト ID・列の内部名などが分からない場合は、生成せずに質問する。コネクタのアクションの書き方は知識から作ってよいが、未検証として伝える。
- **作れる依頼はすぐ作る。** 必要な情報がそろい、解釈が 1 つに定まる場合は、計画の提示や追加の確認をせず生成へ進む。
- **外枠はビルダーで作る。** パッケージの構造は `scripts/pa_package_builder.py` で作り、手で組み立てない。
- **作成者以外が読めるフローにする。** アクション名とメモは、`references/design-standards.md` の基準に従う。
- **詳しい判断の前に参照ファイルを読む。** この `SKILL.md` は判断と手順だけを記載する。詳細は下の表から必要なファイルだけを読む。

## 依頼の言語

このスキルには日本語版と英語版がある。**どちらの版を使っても、同じ依頼には同じ結果を返す。** 出力の言語は、スキルの版ではなく依頼の言語で決める。

| 依頼の言語 | 返答・質問 | アクション名の区切り | メモ |
|---|---|---|---|
| 日本語 | 日本語 | 全角コロン (`項目の作成：試験情報の登録`) | 日本語 |
| 英語 | 英語 | 半角スペース + ハイフン + 半角スペース (`Create item - Register study`) | 英語 |

- 依頼の言語は、製品名、列名、コード、JSON などを除いた文章の言語で判断する。
- 日本語と英語が混在する場合は、文章の大半を占める言語に合わせる。
- 依頼者が言語や命名を明示した場合は、その指定に従う。
- `verify_package` の `lang` には、日本語なら `ja`、英語なら `en` を渡す。

## 対象外

- ソリューション形式のパッケージ
- 子フロー (非ソリューション フローでは使用できない)
- Power Automate の環境へ直接インポートする操作 (zip を渡すところまで)

対象外の依頼は、その旨を伝えて終了する。

## 依頼の状態と次の行動

| 依頼の状態 | 次の行動 | 読む参照ファイル |
|---|---|---|
| 必要な情報がそろい、解釈が 1 つに定まる | 生成する | `design-standards.md`、`package-structure.md`、該当するトリガーとコネクタの参照ファイル |
| 環境ごとの値 (リスト ID、列の内部名など) が足りない | 足りない値と取得方法を示して質問する | `intake.md`、該当するコネクタの参照ファイル |
| 解釈が複数に分かれる、要件同士が矛盾する | 選択肢を付けて質問する | `intake.md` |
| インポートや実行でエラーが出たと報告された | エラー内容から原因を特定し、差分だけ修正する | `revision.md` |
| 生成済みのフローの変更を依頼された | 差分だけ修正する | `revision.md` |

## 参照ファイル

| ファイル | 内容 |
|---|---|
| `references/intake.md` | 必要な情報、質問の判断基準、質問の出し方、依頼テンプレート |
| `references/design-standards.md` | アクション名、メモ、スコープ、条件分岐、データ処理の設計基準 |
| `references/package-structure.md` | パッケージの外枠 (確認済みの構造) |
| `references/triggers-and-auth.md` | トリガーの種類と、接続・認証の形式 |
| `references/sharepoint.md` | SharePoint のアクションのパラメーター、列の種類、列定義の確認方法 |
| `references/output-format.md` | 生成時に返す内容の形式 |
| `references/revision.md` | エラー報告と修正依頼への対応 |

## 処理手順

1. 依頼を読み、依頼の言語と、上の表の依頼の状態を判断する。
2. 該当する参照ファイルを読む。
3. 質問が必要な場合は、`intake.md` の形式で 1 回にまとめて質問し、回答を待つ。生成はしない。
4. 生成する場合は、`design-standards.md` に従ってアクション名とメモを決め、ビルダーでパッケージを作る。
5. `verify_package` を実行する。エラーは直す。警告は、推測で消さずに未確認事項として報告する。
6. `output-format.md` の形式で、zip と設計の要約を返す。

## 回答前の確認

- 推測で値や処理を補っていないか。補った箇所があれば、生成をやめて質問に切り替える。
- 作れる依頼に、不要な質問をしていないか。
- 返答、アクション名の区切り、メモが、依頼の言語に合っているか。
- アクション名が「元のアクション名 + 区切り + 処理内容」の形になっているか。
- メモが必要なアクションに、背景や理由を説明するメモがあるか。
- `verify_package` でエラーがないか。
- 未確認事項を、確認済みの事項と混ぜずに伝えているか。
