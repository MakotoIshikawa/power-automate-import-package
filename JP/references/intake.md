# 依頼の受け付けと質問

質問とテンプレートは、依頼の言語で示す。

## 生成に必要な情報

1. **フローの目的**：何を自動化するか
2. **トリガー**：手動、スケジュール、項目やファイルの作成時など。手動の場合は入力項目
3. **処理の順序**：アクション、条件分岐、繰り返し
4. **項目の対応**：入力のどの値を、どこへ、どの形で設定するか
5. **環境ごとの値**：サイト URL、リスト ID、列の内部名、列の種類、選択肢の値、参照列の参照先、Teams のチーム ID とチャネル ID など

会話や過去の作業ですでに確認済みの値は、再確認しない。

## 質問する場合

次のどれかに当たる場合は、生成せずに質問する。

- 環境ごとの値が足りない (推測で ID や内部名を作らない)
- 解釈が複数に分かれ、結果のフローが変わる
  - 例：「通知する」の送信先が、作成者か、担当者列の人か、固定の宛先か分からない
  - 例：複数件が該当したときに、すべて処理するか、最初の 1 件だけか分からない
- 要件同士が矛盾している
- 対象外の機能 (子フロー、ソリューション形式) が必要になる

## 質問しない場合

次の点は、このスキルの基準で決める。質問しない。

- アクション名とメモの文面 (`design-standards.md` に従う)
- アクション名とメモの言語 (依頼の言語に合わせる)
- スコープのまとめ方、内部の変数の使い方
- 依頼に書かれていない処理を追加しないこと (エラー処理、通知、重複確認などは、依頼がなければ作らない)

## 質問の出し方

- 質問は 1 回にまとめる。回答を待ってから生成する。
- 番号を付け、選択肢を示す。選択肢によってフローがどう変わるかを 1 行で添える。
- 推奨案がある場合は理由を添えて示す。ただし、回答がないまま推奨案で生成しない。
- 環境ごとの値は、取得方法 (確認 URL など) を一緒に示す。

例

```
生成の前に 2 点確認させてください。

1. 該当する項目が複数ある場合の扱い
   - A. すべての項目に通知する (「それぞれに適用する」で繰り返す)
   - B. 最初の 1 件だけ通知する
2. 担当者列の内部名
   次の URL を開き、結果を貼り付けてください。
   (確認 URL)
```

## 依頼テンプレート

最初の依頼が短い場合は、次のテンプレートを示して記入してもらう。全部を埋める必要はなく、分かる範囲でよいことを伝える。

```
【フローの目的】
【トリガー】手動 / スケジュール (頻度、時刻) / 項目やファイルの作成時など
【手動の場合の入力項目】
【処理の流れ】1. 2. 3.
【項目の対応】入力の値 → 設定先の列
【データソース】サイト URL、リストの URL
【複数件が該当した場合】すべて処理 / 最初の 1 件だけ
【やらないこと】エラー処理、通知など、今回は不要なもの
```
