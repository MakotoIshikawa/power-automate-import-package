# フローの設計基準

作成者以外の人が、フローを開いたときに処理の流れと意図を理解できることを目的にする。

## アクション名

**元のアクション名を残し、区切りの後ろに処理内容を書く。** 区切りとアクション名の言語は、依頼の言語で決める。ビルダーの `action_name(base, purpose, lang)` で作る。

| 依頼の言語 | 区切り | 例 |
|---|---|---|
| 日本語 (`ja`) | 全角コロン `：` | `項目の作成：試験情報の登録` |
| 英語 (`en`) | ` - ` (半角スペース、ハイフン、半角スペース) | `Create item - Register study` |

元のアクション名の例

| 日本語の既定名 | 英語の既定名 | 日本語の例 | 英語の例 |
|---|---|---|---|
| 作成 | Compose | 作成：ユーザー名 | Compose - User name |
| 変数を初期化する | Initialize variable | 変数を初期化する：検索条件 | Initialize variable - Search filter |
| 項目の取得 | Get item | 項目の取得：ユーザーデータ | Get item - User data |
| 項目の作成 | Create item | 項目の作成：試験情報の登録 | Create item - Register study |
| アレイのフィルター処理 | Filter array | アレイのフィルター処理：特定条件の抽出 | Filter array - Extract matching rows |
| JSON の解析 | Parse JSON | JSON の解析：子フローの応答 | Parse JSON - Child flow response |
| それぞれに適用する | Apply to each | それぞれに適用する：国別情報 | Apply to each - Country records |
| 条件 | Condition | 条件：承認済みか | Condition - Is approved |
| スコープ | Scope | スコープ：登録処理 | Scope - Registration |

- 英語の既定名は知識による。デザイナーの表示と違う可能性がある場合は、設計の要約で未確認として示す。
- 半角コロン (`:`) も名前に使えるが、この基準では使わない。
- 定義上の名前 (キー) では、空白を `_` に置き換える。例：`Create item - Register study` のキーは `Create_item_-_Register_study`。式で参照するときもキーを使う。ビルダーの `action_key()` で変換する。
- トリガーの名前は変更しない (`manual`、`Recurrence` など)。

## メモ

**名前だけでは伝わらない背景、条件の意味、設計の理由、注意点を書く。** メモはアクションの `description` に保存される (書き出し結果で確認済み)。メモの言語は依頼の言語に合わせる。

例

- 「作成した試験情報の ID を、後続の国別情報の参照列に設定する」
- 「条件として、ステータス = 有効 を設定している」
- 「親子の対応が崩れないよう、同時実行数を 1 にしている」

メモを必ず付けるアクション

- コネクタのアクション (取得、作成、更新、送信など)
- 条件分岐、スイッチ、繰り返し、スコープ
- JSON の解析、アレイのフィルター処理、選択

「作成」や変数の操作は、名前で意図が伝わるならメモは不要。名前を言い換えただけのメモは書かない。

## 構成

- **スコープ**：関連する処理が 3 つ以上続き、まとめると流れが分かりやすくなる場合に使う。少数のアクションを、まとめるためだけにスコープへ入れない。
- **条件分岐**：入れ子は 2 段までを目安にする。条件の値が 3 通り以上に分かれる場合はスイッチを検討する。
- **データの受け渡し**：変更しない値は「作成」を使う。途中で値を更新する必要がある場合だけ変数を使う。
- **配列**：配列の形を変えるだけなら「選択」、絞り込むだけなら「アレイのフィルター処理」を使い、不要な繰り返しを作らない。
- **繰り返し**：前の処理の結果を後の処理で使う場合や、親子の対応を取る場合は、同時実行数を 1 にする。

```json
"runtimeConfiguration": {"concurrency": {"repetitions": 1}}
```

## 過剰に適用しない

- 整理を目的に、依頼にない処理やスコープ、変数を追加しない。
- 複数件を処理する要件を、`first()` などで 1 件だけの処理に変えない。
- シンプルさを優先する。高度な式を詰め込むより、読みやすいアクションの並びを選ぶ。
