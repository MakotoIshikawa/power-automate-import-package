# 📦 power-automate-import-package

[English](README.md) | 日本語

自然言語の依頼から、Power Automate の非ソリューション フロー用インポート パッケージ (.zip) を作るエージェント用スキルです。

フローの内容とデータソースを文章で伝えると、スキルがパッケージを作り、構造を検査して、設計の要約と一緒に返します。依頼があいまいな場合は、推測で作らずに質問を返します。

> [!NOTE]
> Microsoft の公式製品ではありません。

## ✨ 特徴

- **推測で作らない**：依頼の解釈が分かれる場合や、リスト ID・列の内部名などが足りない場合は、生成する前に選択肢を付けて質問します。
- **作れる依頼はすぐ作る**：必要な情報がそろっていれば、追加の確認をせずにパッケージを作ります。
- **読みやすいフロー**：アクション名は元のアクション名を残し、処理内容を添えます。名前だけでは伝わらない背景や設計の理由は、メモに書きます。
- **依頼の言語に合わせる**：どちらの版のスキルでも、同じ依頼には同じフローを返します。返答、アクション名、メモは依頼の言語に合わせます。

  | 依頼の言語 | アクション名の例 |
  |---|---|
  | 日本語 | `項目の作成：注文の登録` |
  | 英語 | `Create item - Register order` |

- **修正の往復を減らす**：パッケージと一緒に、設計の要約、項目の対応表、確認済みと未確認の点、インポート後に確かめる項目を返します。
- **構造の検査**：同梱の Python のビルダーが、パッケージの外枠を作ります。インポートの前に、次のものを検出します。
  - 存在しないアクションを参照する式
  - `runAfter` の誤り
  - アクション名の重複
  - メモの不足

## 🧭 処理の流れ

```text
自然言語の依頼
  ↓
依頼の言語と、作れる状態かを判断
  ├─ 値の不足、解釈が分かれる → 選択肢を付けて質問
  └─ 作れる → ビルダーでパッケージを作成
               ↓
             構造を検査
               ↓
             zip と設計の要約を返す
               ↓
Power Automate でインポートしてテスト実行
  ↓
エラーや変更を伝える → 差分だけ修正
```

## 📋 必要な環境

- エージェントが Python 3 を実行し、zip ファイルを出力できる環境
  - ビルダーは Python の標準ライブラリだけを使います。
- パッケージをインポートできる Power Automate の環境

> [!IMPORTANT]
> Copilot in SharePoint のスキルはカスタム コードを実行できないため、このスキルでパッケージを作ることはできません。

## 🚀 インストール

このリポジトリの Releases ページから、使う版の zip をダウンロードしてください。

| ファイル | 版 |
|---|---|
| `power-automate-import-package_JP.zip` | 日本語版 |
| `power-automate-import-package_EN.zip` | 英語版 |

どちらの版でも結果は同じです。読みやすく、管理しやすい言語の版を選んでください。

### Copilot Studio

GitHub Copilot harness で作ったエージェントを使います。

1. エージェントを開き、**Build** タブを選びます。
2. **Skills** から **Add skill**、**Upload a skill** の順に選びます。
3. zip ファイルをそのままアップロードします。

### Agent Builder

Agent Builder のスキルはプレビュー機能で、組織が Microsoft Frontier Program に参加している必要があります。

1. Agent Builder でエージェントを開くか、新しく作ります。
2. **構成** タブで **スキル** を展開し、**追加** を選びます。
3. zip ファイルをそのままアップロードします。

### Skills フォルダーに置く場合

`JP/` または `EN/` フォルダーをコピーし、フォルダー名を `power-automate-import-package` に変えてください。フォルダー名は `SKILL.md` の `name` と一致させる必要があります。

## 💬 使い方

フローの内容とデータソースを文章で伝えてください。リスト ID や列の内部名など、環境ごとに違う値が必要です。

依頼の例

```text
手動でトリガーするフローを作ってください。
入力に JSON のテキストを受け取り、records 配列の各レコードを
注文リストに登録します。

サイト：https://contoso.sharepoint.com/sites/Sales
リスト ID：00000000-0000-0000-0000-000000000000
項目の対応：
- orderNumber → Title
- customerName → CustomerName
- amount → Amount (数値)
すべてのレコードを登録してください。
```

依頼が短い場合は、スキルが次のテンプレートを示します。

```text
【フローの目的】
【トリガー】手動 / スケジュール (頻度、時刻) / 項目やファイルの作成時など
【手動の場合の入力項目】
【処理の流れ】1. 2. 3.
【項目の対応】入力の値 → 設定先の列
【データソース】サイト URL、リストの URL
【複数件が該当した場合】すべて処理 / 最初の 1 件だけ
【やらないこと】エラー処理、通知など、今回は不要なもの
```

リスト ID や列の内部名が分からない場合は、取得用の SharePoint REST API の URL をスキルが示します。ブラウザーで開いて、結果を貼り付けてください。

インポートしたら、設計の要約にある確認項目に沿ってテスト実行の結果を確かめてください。エラーが出た場合は、エラーメッセージか、失敗したアクションの出力を伝えてください。スキルは差分だけを修正し、新しいバージョンとして作り直します。

## ✅ 確認済みの範囲

| 項目 | 状況 |
|---|---|
| 手動トリガー + SharePoint の「項目の作成」 | インポートと実行を確認 |
| 参照列でつないだ親子 2 リストへの登録 | インポートと実行を確認 |
| メモが `description` に保存されること | 書き出し結果で確認 |
| スケジュール トリガー | 書き出し結果でトリガーを確認。インポートは未確認 |
| SharePoint の自動実行トリガー (ファイルが作成されたとき) | 書き出し結果でトリガーを確認。インポートは未確認 |
| スケジュールや自動実行のフローでのコネクタのアクション | 未確認 (認証は推論で設定) |
| SharePoint の「項目の作成」以外のアクション | 知識から作成し、未検証として報告 |

生成したパッケージごとに、未検証の点をスキルが報告します。

## 🚫 対象外

- ソリューション形式のパッケージ
- 子フロー (非ソリューション フローでは使用できない)
- Power Automate の環境への直接のインポート

## ⚠️ 注意事項

- 生成したフローは、本番で使う前に必ずテストしてください。
- パッケージの形式は、確認した時点の書き出し結果に基づいています。インポートできなくなった場合は、形式が変わった可能性があります。
- 構造の検査に通っても、インポートできることは保証されません。

## 🙏 謝辞

`SKILL.md` の構成 (本体を簡潔にし、参照ファイルは必要なときだけ読み込み、作れる依頼はすぐ実行に移る) は、Copilot in SharePoint の Microsoft の `sharepoint-automation` スキルを参考にしました。このリポジトリには、そのスキルのファイルは含まれていません。
